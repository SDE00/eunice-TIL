## Learned
### 1. 스프링 등장 배경

| 구분   | EJB (이전) | Spring (이후) |
| ---- | -------- | ----------- |
| 복잡도  | 높음       | 낮음          |
| 성능   | 낮음       | 개선됨         |
| 진입장벽 | 높음       | 낮음          |
| 설정   | 직접 관리    | 프레임워크가 관리   |

- EJB는 이론적으론 훌륭하지만 느리고 복잡함 → 스프링은 이를 단순화한 대체 프레임워크로 등장

### 2. 스프링의 핵심 개념

| 개념           | 설명                         |
| ------------ | -------------------------- |
| IoC (제어의 역전) | 객체의 생성과 생명주기를 스프링 컨테이너가 담당 |
| DI (의존성 주입)  | 객체 간 의존성을 외부 설정을 통해 주입     |
| AOP          | 공통 관심사(로깅, 트랜잭션 등) 분리      |
| POJO         | 순수 자바 객체로 복잡한 상속 없이 구현 가능  |

- 결과적으로 디커플링(모듈 간 결합도 낮춤), 테스트 용이성, 유지보수성 강화

### 3. 스프링 vs 스프링 부트

| 항목 | Spring          | Spring Boot                |
| -- | --------------- | -------------------------- |
| 설정 | 수동 설정           | 자동 설정 (starter, config 포함) |
| 서버 | 외부 WAS 필요 (WAR) | 내장 WAS (JAR)               |
| 실행 | war 파일 빌드 후 배포  | jar 파일 실행만으로 서버 기동    |
| 목적 | 유연성 중시          | 개발 편의성 중시                  |

- Spring Boot는 초기 설정 부담을 줄이고, 마이크로서비스에 적합한 경량화 구조 제공

### 4. Spring Boot 실행과정 핵심 흐름

```java
@SpringBootApplication
public class MyApp {
  public static void main(String[] args) {
    SpringApplication.run(MyApp.class, args);
  }
}
```

| 단계 | 설명                                           |
| -- | -------------------------------------------- |
| 1  | SpringApplication 인스턴스 생성 및 실행               |
| 2  | 배너 출력 (banner.txt 또는 기본 배너)                  |
| 3  | ApplicationContext 생성 및 Bean 스캔              |
| 4  | @Configuration, @Component, @Controller 등 등록 |
| 5  | ServletWebServer 생성 (내장 톰캣)                  |
| 6  | DispatcherServlet 자동 등록                      |
| 7  | 컨트롤러 및 핸들러 매핑 등록                             |
| 8  | 요청 수신 및 처리 시작                                |

### 5. DispatcherServlet 동작 흐름

#### 요청 처리 흐름도

```
[Client] → DispatcherServlet 
        → HandlerMapping → HandlerAdapter → Controller 
        → ViewResolver → View → Response
```

| 단계 | 설명                                 |
| -- | ---------------------------------- |
| 1  | HTTP 요청 수신                         |
| 2  | HandlerMapping으로 요청에 맞는 컨트롤러 탐색    |
| 3  | HandlerAdapter로 컨트롤러 실행            |
| 4  | 컨트롤러 실행 결과를 View로 반환하거나 JSON 응답 생성 |
| 5  | 클라이언트에 응답 반환                       |

※ @RestController 사용 시 ViewResolver 생략되고, MessageConverter가 직접 응답 작성

### 6. 서블릿 컨테이너 개념

| 요소        | 역할                           |
| --------- | ---------------------------- |
| 요청 수신     | HTTP 요청 가장 먼저 수신 (예: Tomcat) |
| 생명주기 관리   | 서블릿 객체의 생성, 초기화, 소멸 관리       |
| 스레드 관리    | 요청마다 별도 스레드 할당 및 병렬 처리       |
| 보안 처리     | 인증, 세션, 쿠키 관리                |
| 정적 리소스 제공 | JS, CSS, 이미지 등 직접 제공 가능      |
